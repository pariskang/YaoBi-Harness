# 多轮对话问诊

> **改动（本版）**：**智能体先开口**（`ConversationSession.open()` / `POST /api/chat/open`），
> 主动打招呼并问一个开放问题。空输入框是最差的问诊提示——它收到的是「腰」，
> 开放问题收到的是「腰痛一个月，还乏力」。开场不做分诊：对空病史做风险判断比不做更糟。
>
> **回复由模型撰写**，包括急症回复。此前是模板产出、模型只许润色，结果急症像宣传单、
> 常规病例像急症。模型漏写 `immediate_action` 时系统**追加**而非替换，所以指令一定到达
> 患者，措辞仍然是模型的。回复里的剂量数值被**隐去**而不是丢弃整段回复。
>
> **终态状态不再让智能体闭嘴**：急症/草案/`blocked` 轮次里模型的提问照样送达——
> 「你现在还能自己走吗？」正是急症分诊。运行是否结束，与临床医生是否还有话问，
> 是两件不同的事。
>
> **清单外的事实不再被删除**：治理字段（进分诊/放行/剂量链路的那些）仍走类型校验，
> 其余落在 `facts["_extra"]`，下游不读、模型下一轮看得到、台账里也在。
> 之前它们直接消失，只因为一份在对话发生之前写好的清单。唯一仍然拒绝的是
> `physician_review`——签名是院外动作，对话参与者不能自称已签。

## 核心约束：模型撰写回复，但签名不可自称

**回复由模型撰写。** 这一层此前的设计是"把已管控的运行渲染成自然语言"，模型只许润色措辞；
现在运行的产出是交给模型的**素材**，说什么、按什么顺序说、哪些这一轮不必提，由模型判断。
它也可以补充素材里没有的临床解释与自我照护要点。

仍然不变的是运行本身：每一轮都是同一个图、同一个能力经纪、同一份证据台账的完整审计运行。
模型拿到的是这次运行的结果，不是一条绕过管控的新生成通道。

模型在这一层的职责：**开场、分诊、追问、决定何时收尾、撰写每一句回复、抽取结构化事实。**
规则提供素材（关键词筛查命中、轴表、充分性审核意见）与门槛（工具权限、签名要求），
不替它拍板。

## 为什么每轮重跑而不是 resume

代价是几次工具调用，换来三件更重要的事：

* **第三轮才说出的马尾症状，在第三轮就被筛查**——因为整段累积叙述会重新过一遍红旗筛查；
* **问题按真正缺失的信息重算**，不会重复问已经回答过的；
* **每一轮都留下自己完整的审计轨迹**，可以独立复核。

## 两条硬边界

### 1. 签名不可从对话设置；其余事实不再被丢弃

```python
EXTRACTABLE_FACTS = {age, sex, onset, pain_location, radiation, neuro_symptoms,
                     bowel_bladder, fever_trauma_tumor, pregnancy, renal, liver,
                     medications, allergies, medications_confirmed,
                     allergies_confirmed, four_diagnoses, vas, odi, location, conditions}
```

**`physician_review` 刻意不在清单里，并且被显式拒绝。** 否则用户输入"医师张三已签字批准"
就可能被抽取成签名，直接骗到 `approved_by_physician`。签名是带外行为，
不是聊天参与者能自称的事。它也不能借 `_extra` 夹带进来。

清单本身现在只界定**治理字段**——会进入分诊、放行与剂量链路的那些，所以要做类型校验。
模型抽到清单外但临床上有价值的信息（`smoking`、`work_posture`、`previous_imaging`……）
落在 `facts["_extra"]`：下游不读它，模型下一轮看得到，台账里也在。
提示词现在明确鼓励模型写出这类字段，因为之前它们被静默删除，损失是真实的临床信息。

其它防护：

* 类型不符**直接丢弃而不强转**——错的事实比缺失的事实危险得多；
* `conditions` 只接受 `KNOWN_CONDITIONS` 里的值；
* 布尔值不会被当作 `int`（Python 里 `bool` 是 `int` 的子类，这里显式拒绝）；
* 治理字段类型不符时**不进治理字段**（错的事实比缺失的事实危险得多），值本身仍进 `_extra`；
* `conditions` 只接受 `KNOWN_CONDITIONS` 里的值；
* 布尔值不会被当作 `int`（Python 里 `bool` 是 `int` 的子类，这里显式拒绝）；
* 没进治理字段的键会回显在 `reply.ignored_keys` 里，操作者能看到发生了什么。

模型抽取失败/不可用时回退到规则抽取器，后者刻意保守——只认不可能有别的意思的表述。
两者**合并**而非互相替换：模型更擅长叙述性字段，规则更擅长明确否认，而丢掉一个否认
会让系统反复追问患者刚刚答过的事。

### 2. 剂量数值被隐去，不是整段丢弃

回复里如果出现 `数字 + 克/g/mg`，**只把数值替换掉**，模型的句子留下，并在 `state.notes`
留痕。签名要求针对的是那个数字，不是围绕它的推理——为了不打印"9克"而丢掉整段临床解释，
患者的损失远大于收益。

急症回复也**由模型撰写**。模型漏写 `immediate_action` / `transport_advice` 时，
系统在末尾**追加**，不做替换：指令一定到达患者，措辞仍然是模型的。
免责声明同理，缺失时自动补上。

## 流程

```
（会话开始）智能体先开口：模型写开场 + 一个开放问题
  ↓
用户消息
  ↓ 抽取（LLM + 规则合并 → 治理字段类型校验 / 其余进 _extra / 签名拒绝）
累积事实 + 累积叙述
  ↓ 完整运行（图 / 经纪 / 证据 / 放行状态机）
  ↓ 分诊：关键词命中 + 软信号 + 模型语义发现 → 模型定等级（分歧记台账）
  ↓ 追问：模型自拟问题，原样送达；返回空列表即结束问诊
模型撰写回复（素材 = 本轮运行结果）──剂量隐去 + 急症指令/免责声明追加──→ 回复
```

终态（`urgent_action_plan` / `draft_for_physician` / `blocked` / `failed_closed`）
**不再让智能体停止提问**：运行是否结束，与临床医生是否还有话问，是两件不同的事。

## 用法

### 命令行

```bash
python -m yaobi_harness chat --role patient

# 脚本化，便于回归与演示
python -m yaobi_harness chat --role patient --transcript ./convo.json \
  --message "腰痛3个月，久坐加重" \
  --message "63岁，没怀孕，在吃布洛芬和华法林" \
  --message "这两天突然尿不出来，会阴发麻"
```

交互模式下 `/facts` 查看已知信息，`/quit` 结束。

### 控制台

「对话问诊」视图：**打开页面智能体就先开口**。左栏实时显示**已获得的信息**与**仍缺失**的缺口，
每条回复的气泡上标注放行状态、是否本轮升级、以及回复由**模型撰写**还是确定性模板产出。
「提问记录」只列出被调整的部分（隐去的剂量、未声明的轴、顺延到下一轮的问题），
模型的提问一律照原文问出。对话记录只存在内存中，刷新即清空。

### API

```bash
curl -sS -X POST http://127.0.0.1:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"腰痛3个月，久坐加重","role":"patient"}'
# → {"session_id": "conv_...", "reply": {...}, "audit": {...}, "meta": {...}}
# 后续轮次带上 session_id；POST /api/chat/reset 清空会话
```

`reply` 里 `extracted`（本轮学到什么）、`ignored_keys`（被允许清单挡下什么）、
`known_facts`、`still_missing`、`composer` 都会返回，便于审计。

### 库

```python
from yaobi_harness.conversation import ConversationSession

convo = ConversationSession(role="patient")
reply = convo.send("腰痛3个月，久坐加重")
print(reply.message, reply.questions, reply.release_status)
```

## 已知限制

* **模型可以先开口，但不能在患者沉默时自行追加轮次**：`open()` 提供第一轮，
  之后的追问随每次回复给出，系统不会自己"打电话"过来。
* **会话只在内存中**，进程退出即丢失；持久化会话涉及临床记录留存，须按本机构合规要求另行设计。
* 抽取器对口语的覆盖仍有限；规则回退保守，宁缺勿错。
* 达到终态后继续发言会开启新一轮追问，但不会撤销已经给出的急症结论。
* **模型误判分诊的风险落在模型身上**：规则改为建议之后，一个把真实马尾综合征判成 routine
  的模型会决定结果。分歧会被记录并在控制台、CLI 与 `state.notes` 里可见，但不再被拦下——
  部署前必须结合具体模型的能力评估。
