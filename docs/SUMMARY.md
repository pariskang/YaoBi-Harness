# 病历摘要：结论之后交出去的那份东西

系统其余部分都是给机器看的——证据 ID、放行状态、能力校验。这一层产出的是**临床医生
真正需要的那份文件**：按门诊病历节次排列的结构化文本，可以直接粘进病历系统。

```bash
python -m yaobi_harness run --complaint "..." --facts '{...}' --summary
python -m yaobi_harness chat --role patient      # 对话中输入 /note
```

控制台：得出结论后，「单次运行」页出现**病历摘要**标签，可切换分节/纯文本并一键复制。

## 节次

主诉 / 现病史 / 既往史与用药 / 中医四诊 / 查体与量表 / 辅助检查与影像 /
西医诊断（鉴别）/ 中医诊断与证型 / 风险评估与红旗 / 用药安全 / 治疗计划 /
处方草案 / 医嘱与自我照护 / 随访与复诊指征 / 不确定性与局限

顺序是固定的——中国门诊骨科病历就是按这个顺序写、也按这个顺序读的。
末尾附**引用来源**（来源/版本/许可/检索时间）与**证据台账**（可放行证据的 ID）。

## 三条设计要点

### 不新增任何临床事实

每一节都填自 `state.outputs`、`state.facts` 与证据台账。没有来源的节印成**「未采集」**
而不是省略——一份悄悄漏掉既往史的病历，读起来像"没有相关既往史"，
那是和"没问过"完全不同的临床断言。

模型撰写叙述节次时也一样：`yaobi.clinical_summary` 的技能说明写明"这是整理，不是新增"，
而且**模型留空的节会回落到运行已确立的内容**，不会因为模型漏写而消失。

### 有剂量当且仅当确定性链路产出了剂量

处方一节**原样复现**草案：逐味药名、剂量、授权药典范围、样本量、风险标记、
**逐味签名状态**。其余各节不含克数——治疗计划只写"组成（不含剂量）"。
模型写的叙述若出现克数会被隐去（`redact_doses`），但**不作用于处方一节**：
那一节的数字来自确定性链路，且签名状态就印在旁边。

### 它会说明自己是什么

未经医师逐味签名的摘要，`status_label` 是「草案 · 未经医师签名」，
而且这个标记是**结构的一部分**（`ClinicalNote.status_label`），
不是文末一行小字——所以只渲染已知字段的前端也丢不掉它。

## 什么时候生成

只有运行**得出结论**才生成：`treatment_advice_only` / `draft_for_physician` /
`approved_by_physician` / `urgent_action_plan` / `needs_examination`。
对未完成的病史出病历，是一份误导性文件。

生成发生在 `_finalize` 的最后一步，而不是任务图里的一个节点：放行状态是在 `_finalize`
里定下来的，一个排在图中间的任务永远只会看到 `needs_more_information` 并跳过。
它也**不在 `AGENT_CATALOG` 里**，所以 LLM 规划器无法把它排到一个没有意义的位置。

## 成本

确定性拼装是免费的，每轮都做。**模型撰写的版本在多轮对话里只在问诊收尾时跑一次**——
判据是 `open_questions` 为空。否则一次六轮的对话要为六份摘要付费，而只有最后一份会被读。
单次运行（没有下一轮可等）则立即撰写。

## 角色范围

摘要在**医师视图**与操作者审计里，**不在患者视图**。它写了证据 ID、审核者与规则的分歧、
未闭合的必答轴——那是临床医生的工作记录，患者拿到的是回复本身。

## 已知限制

* 线上问诊**没有查体**。「查体与量表」一节只有患者自述的评分，并明确标注。
* 影像判读是 `model_reasoning` 等级，摘要里会带「**非影像报告，需正式阅片**」。
* 摘要不含患者身份信息，也不应被当作可归档的正式病历——
  归档需要院内 HIS 的身份绑定与签名流程，那不在本仓库范围内。
